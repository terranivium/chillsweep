# ChillSweep — working notes

Tauri 2 Windows app that finds what uninstalled apps, caches, dev projects and games left behind.
Rust in `src-tauri/src/` (scan signals in `signals/`, knowledge base in `rules/default.toml`), plain
HTML/JS/CSS frontend in `src/`, icon generated by `brand/build-icon.mjs`.

## Hard constraints

- **Log user-facing changes in `CHANGELOG.md` as you make them.** Any fix or change a user would notice
  gets a bullet under `## Unreleased`, in the user's words rather than commit-speak. That section becomes
  the release notes and the in-app What's new. Skip it for internal-only work (refactors, tooling,
  docs, tests).
- **Don't run `npm run release` or other production builds unless asked.** They're slow, and `release`
  uploads to GitHub.
- **Scanning never launches other programs or changes anything.** Removal is always explicit, re-checked,
  and goes to the Recycle Bin (except safe-to-clear items the user opts to delete permanently).
- **The only network call the app makes is the update check** against this repo's GitHub releases. Treat any
  proposal to add another one as a decision for the user, not a tweak.
- **Commits and PRs carry no Claude attribution:** no `Co-Authored-By: Claude` trailer and no
  "Generated with Claude Code" line.

## Releasing

The full process is in **`RELEASING.md`**; read it before driving a release. The rules that matter most,
because getting them wrong is expensive:

- **Publishing *is* shipping the update.** It reaches every installed copy. **Never publish a release on
  the user's behalf.** Leave it a draft and say it's ready.
- **`npm run release:check` before publishing.** It's read-only and asserts the installer, `.sig` and
  `latest.json` are all there and agree with each other. A broken feed fails silently in the field.
- **`CHANGELOG.md` is the source of truth for release notes**, past and present. Never write notes in the
  GitHub UI. `npm run release-notes -- --notes=1.42.0` corrects a published release, and
  `npm run changelog:promote` closes a version out after publishing.
- **The version is `1.{git rev-list --count HEAD}.0`.** Make a commit between releases, or the new one is
  never offered as an update.
- **Secrets live in the gitignored `release.env`** (`GH_TOKEN`, the updater signing key path and its
  password). Never print, echo or commit them. `release.env.example` is the committed template.
